① 模型侧反推：H3 一次生成到底算了多少账

由公开架构数据推导 token 数与计算量 —— 这是"预估时间"的第一块基石。

Token 数：VAE f16t4d24（空间 16×、时间 4×）→ patchify 1×2×2（t×h×w），故进入 Transformer 的视觉 token = (H/32)×(W/32)×(帧数/4)，帧数 = 时长×24fps
每步计算量：FLOPs ≈ 2 × P_eff × token（dense 前向，P_eff ≈ 20B）
算力下限：T_flops = FLOPs × 步数 ÷ 稠密INT8算力　带宽下限：T_band = 权重字节 × 步数 ÷ 显存带宽
分辨率像素5s token15s token5s FLOPs(20步)15s FLOPs(20步)
关键结论一：INT8 量化后模型只剩 19.5GB，带宽下限低到可忽略。以 6000PRO（1792GB/s）算 0.4MP·5s 的带宽下限仅 0.22s（19.5GB×20步÷1792GB/s ≈ 0.22s），远小于实测 58s。因此本任务在 INT8 下是算力受限 + 注意力/调度开销型负载，而不是显存带宽受限 —— 单看带宽猜速度会完全失真。
关键结论二：注意力的超线性膨胀。1MP 的 token 是 0.4MP 的 2.55 倍，但 6000PRO 实测 198s/58s = 3.41 倍 —— 序列越长，注意力与 KV 缓存开销占比越高，效率随分辨率下降。

示例：3090 跑 BF16（×2.0）且 Ampere 无 FP8 加速（×1.4）→ 2.8× ≈ 实测 2.79×；4060Ti 跑 BF16（×2.0）× 卸载（×1.5）→ 3.0× ≈ 实测 2.68×；10GB 3080 + 32GB RAM + PCIe3.0 → 卸载(×3) × 内存swap(×1.4) × PCIe(×1.4) ≈ ×5.9 —— 这才是"未魔改 3080"的真实预期，与 20GB 版(×1.3)差出 4 倍。
注意"同名卡、不同显存"：3080 实际有三个版本 —— 10GB(320bit/760GB/s，本文档算力行口径)、12GB 原厂(384bit/912GB/s、CUDA 核更多)、20GB 魔改(320bit 不变、颗粒 1GB→2GB，带宽算力不变仅容量翻倍)。它们算力差异很小，但容量 10→20GB 让卸载系数从 ×2.5~4 降到 ×1.2~1.5，耗时可直接差 2~3 倍 —— 台账若混报三个版本，中位数会被"20GB 魔改版"拉快，这正是 3080 实测(340s)快于 10GB 版理论下限(483s)的最可能原因。

★ 实测校准（真机验证：3080 20G魔改 · 64GB RAM · PCIe4.0 · INT8剪枝扩散 + NVFP4编码器 + SageAttention + EasyCache）
三个实测点：0.4MP/4s=148s（7.4s/it，token 9720，效率 2.28×）→ 1MP/4s=560s（28s/it，24768，3.39×）→ 0.5MP/15s=1320s（66s/it，45900，4.31×）。token ×4.72 而实测时间 ×8.92 → 15s 超线性 1.89×，命中模型"时长拉长注意力膨胀更陡（~1.8）"的预期。
拟合效率曲线：E ≈ 2.28 × (token/9720)^0.41（三点误差 <2%）→ 折算 0.4MP/5s ≈ 203s（台账 3080 中位 340s，快 1.7×）；1MP/5s ≈ 760s（台账 2981s，快 3.9×）。
校准结论：① 卸载系数回调至 ×1.0~1.1：20GB 恰装 19.5GB 权重、NVFP4 编码器少量换出、PCIe4 快速回流 → 实测贴近算力下限，此前 ×1.3 高估了惩罚；② 效率系数不是常数：6000PRO 基准口径 ≈6×，本机优化配置按 E≈2.28×(token/9720)^0.41 从 2.28× 涨到 4.31×（15s）→ 台账"中位秒数"是平均配置，真机优化后可快 2~4 倍（计算器默认 6× 为保守口径）；③ 台账 3080 的 1MP/5s=2981s 样本判定为重度卸载/未优化，应剔除或降权。
三个可复用的规律：① 精度与剪枝是"免费倍数"：INT8→BF16 直接 ×2，未剪枝再 ×1.65，两者叠加 = ×3.3，足以吃掉任何高端卡的硬件优势；② SageAttention 是"追平理论值"的关键（5060Ti/4090 样本吻合组几乎都开了加速）；Ampere 无 FP8 内核理论收益小，但 3080 20G 实测效率 2.28× 显示其 INT8 回退路径仍有可观收益，非"不可用"；③ 只要显存 < 权重体积，卸载系数就主导一切——这就是 16GB 与 96GB 卡同算力却差 2~4 倍的根本原因，也是 6000PRO 作为基准快得"不像话"的原因。

⑦ 结论：数据可信度评估

  1. 整体可信、方向正确：高端与中低端主流卡（5090、4090、5060Ti、5060、4070、2080Ti、5090D）实测中位数与"算力等比"预估偏差在 ±40% 内，说明 6000PRO 台账的主趋势是真实的，各卡相对快慢大体符合硬件算力。
  2. 偏差来自"配置组合"，不是硬件规格：5080/5070Ti/4070S/4060/4060Ti/3090 实测比理论慢 2.3~3 倍，可由"显存卸载(16GB/12GB→×1.5~3) + BF16(×2) + 未剪枝(×1.65)"定量解释（见⑨ 逐卡拆解）。最典型：3090 的 2.79× ≈ BF16×2 与 Ampere 无 FP8 加速×1.4 的乘积；同卡样本极差普遍 3~10× 正是配置差异的直接证据。
  3. 3070/4070tisuper/5070laptop/3060laptop 的 >20× 条目基本不可信：与同卡其它口径（7~20×）断层式冲突。主因依次为 RAM 不足导致磁盘 swap（32GB 以下内存 + 卸载权重 ≈ 42GB 需求）、未加速、后台占用、报数错误，应剔除。
  4. 3060/3080 快于理论已被实测校准：3080 20G魔改 + 64GB RAM 真机实测 0.4MP/4s=148s、1MP/4s=560s（效率系数 2.28~3.39×，见⑨★实测校准），证实 20GB 版卸载 ≈×1.0；台账中位 340s 与 1MP 的 2981s 均为平均/未优化配置，前者快 1.8×、后者快 4.3×，用台账估 3080 必须问"版本 + 是否优化"。
  5. 5090D 数据不足（n=2）：算力阉割 37% 在理论应体现 ~1.6× 差距，实测反而不比 5090 慢，样本太少 + 配置差异无法支撑结论，需更多数据。
一句话结论：这份台账相对排名可信、绝对秒数只代表"该用户的配置"。用它估算某卡耗时，应取同卡同口径的中位数区间，并意识到上下浮动可达 2~4 倍 —— 差异九成来自量化/步数/加速插件/显存卸载，而非显卡本身。

⑧ 反推模型要点（速查）

H3-Base 架构：33B dense 单流全模态 Transformer；约 13B 参数在 AdaLN 分支，推理时预计算缓存不加载 → 有效 ≈20B
编码器：Qwen3-VL-32B（取第50层隐状态），NVFP4 14.6GB / INT8 25.3GB
视频 VAE：f16t4d24（空间16×/时间4×/24通道）+ 1×2×2 patchify
输出：24FPS、默认短边768、最长15s；音频 32kHz 立体声（40Hz latent）
量化体积：BF16 61.7GB → INT8 31.7GB → 剪枝 INT8 19.5GB
给用户的实际建议：① 显存 ≥24GB 才能"扩散全显存"跑剪枝 INT8；16GB 需牺牲编码器精度或接受卸载；<12GB 建议用官方低内存/FP4 路线。② 显存 < 34GB 的卡，内存（RAM）≥64GB 是"能不能流畅跑"的分水岭：42GB 卸载需求若 RAM 只有 32GB，直接落入磁盘 swap，比 PCIe 卸载再慢一个数量级。③ 同分辨率下加大时长 token 数线性涨、但注意力开销超线性涨，15s 比 5s 贵不止 3 倍。④ 5090D 理论应慢 5090 约 1.4~1.6 倍（INT8 阉割 37%），买前请按此心理预期。
